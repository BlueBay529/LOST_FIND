# 찾아드림

서울특별시 중랑구 주민을 대상으로 분실물과 습득물을 검색하고 신고할 수 있도록 개발 중인 팀 프로젝트입니다. ASP.NET Core 서버에서 정적 웹 화면과 API를 함께 제공합니다.

공공데이터는 서울 열린데이터광장과 경찰청 LOST112에서 조회해 최대 50건을 서버 메모리에 저장합니다. 사용자 신고와 실종 반려동물은 별도의 API로 관리합니다. 현재는 데이터베이스를 연결하지 않은 프로토타입 단계입니다.

## 주요 기능

- 기본 정보 → 장소·날짜 → 확인의 3단계 분실물·습득물 신고 화면
- 공공데이터 물품명·특징·분류·보관 상태 검색 및 필터
- 사용자 등록 물품 API의 검색·동네·유형·분류 필터
- 서울 열린데이터광장 습득물 정보 조회
- LOST112 습득물 API 연동 구조
- 중복 공공데이터 통합 및 빈 정보 상호 보완
- 보관 중 물품과 주인이 찾아간 물품 분류
- 전체 습득물 전용 페이지
- PC 메인 물품 카드 3개 한 줄 표시, 하단 그라데이션 및 전체보기 버튼
- 실종 반려동물 전용 신고 화면
- 회원가입·로그인 UI 및 백엔드 API 초안
- 문의, 북마크, 처리 완료 기능 초안
- PC·태블릿·모바일 반응형 화면
- 라이트·다크모드 전환 및 브라우저에 테마 선택 저장
- 공공데이터 최초 조회 재시도 및 매 정시 백그라운드 갱신

## 기술 구성

| 구분 | 기술 |
| --- | --- |
| 프론트엔드 | HTML5, CSS3, Vanilla JavaScript |
| 백엔드 | C#, ASP.NET Core Minimal API |
| 실행 환경 | .NET 10 |
| 현재 데이터 저장 | 서버 메모리, 일부 화면 상태는 브라우저 localStorage |
| 공공데이터 | 서울 열린데이터광장, 경찰청 LOST112 |
| 배포 | Docker, Cloudtype |
| 데이터베이스 | 현재 미연결, MySQL/MariaDB 등 영구 저장소 연동 예정 |

현재 프론트엔드는 React 없이 HTML·CSS·JavaScript로 구현되어 있습니다.

## 로컬 실행 방법

### 준비 사항

- .NET 10 SDK
- Git 또는 GitHub Desktop: 저장소를 내려받아 협업할 경우 필요

### 실행

GitHub에서 저장소를 Clone한 뒤, `LostFind.csproj`가 있는 폴더에서 PowerShell을 열고 실행합니다. 팀원 PC마다 폴더 위치는 달라도 됩니다.

```powershell
$env:ASPNETCORE_ENVIRONMENT="Development"
dotnet run --project .\LostFind.csproj --urls http://127.0.0.1:5098
```

처음 실행하면 필요한 패키지 복원과 빌드가 진행됩니다. `Now listening on: http://127.0.0.1:5098`이 표시되면 아래 주소로 접속합니다.

```text
http://127.0.0.1:5098/
```

전체 습득물 페이지는 아래 경로에서 확인할 수 있습니다.

```text
http://127.0.0.1:5098/items.html
```

- 서버를 유지하려면 실행한 PowerShell 창을 열어 두어야 합니다. 종료는 `Ctrl+C`입니다.
- 각 팀원의 `127.0.0.1`은 각자 자신의 PC를 가리킵니다. 다른 팀원의 PC가 켜져 있을 필요는 없습니다.
- HTML·CSS·JavaScript 수정은 저장 후 새로고침합니다. 이전 내용이 보이면 `Ctrl+F5`를 누릅니다.
- C# 파일을 수정했다면 서버를 종료한 뒤 위 명령으로 다시 실행합니다.
- 5098 포트가 사용 중이면 실행 명령과 브라우저 주소의 포트를 함께 변경합니다.

## 라이트·다크모드

메인과 전체 목록의 상단 해·달 버튼으로 전환합니다. 처음 방문하면 기기의 테마 설정을 따르고, 직접 선택한 뒤에는 브라우저의 `lostfind_theme` 값을 우선 사용합니다.

선택한 모드는 새로고침·페이지 이동·같은 출처의 다른 탭에도 적용됩니다. 신고·로그인 등 팝업과 모바일 메뉴도 테마를 공유합니다. 브라우저 저장소를 사용할 수 없으면 현재 페이지에서만 선택이 유지됩니다.

## 환경변수

| 변수명 | 설명 | 필수 여부 |
| --- | --- | --- |
| `SEOUL_OPEN_API_KEY` | 서울 열린데이터광장 인증키 | 배포 환경에서 서울시 자료 조회 시 필수 |
| `SEOUL_OPEN_API_BASE_URL` | 서울 열린데이터광장 기본 주소 | 선택 |
| `DATA_GO_KR_API_KEY` | LOST112용 공공데이터포털 인증키 | LOST112 사용 시 필수 |
| `LOST112_API_KEY` | LOST112 인증키 대체 변수 | 선택 |
| `LOST112_API_BASE_URL` | LOST112 API 주소 | 선택 |

PowerShell에서 임시 환경변수를 설정하는 예시는 다음과 같습니다.

```powershell
$env:ASPNETCORE_ENVIRONMENT="Development"
$env:SEOUL_OPEN_API_KEY="발급받은_서울시_API_키"
$env:DATA_GO_KR_API_KEY="발급받은_공공데이터포털_API_키"
dotnet run --project .\LostFind.csproj --urls http://127.0.0.1:5098
```

서울시 인증키와 LOST112 인증키는 별개입니다. LOST112를 사용하지 않으면 `DATA_GO_KR_API_KEY`는 생략할 수 있습니다. 위 환경변수는 현재 PowerShell 창에서만 유지됩니다.

현재 코드에는 `Development` 환경에서만 사용하는 서울시 임시 인증키가 있으며, 환경변수를 설정하면 해당 값을 우선합니다. `Production` 배포에서는 이 임시 키를 사용하지 않습니다. 새 인증키와 비밀번호는 소스에 추가하지 말고 환경변수로 관리합니다.

## 주요 API

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| `GET` | `/api/public-items` | 공공데이터 습득물 목록 조회 |
| `GET` | `/api/items` | 사용자 등록 물품 목록 조회 |
| `GET` | `/api/items/{id}` | 사용자 등록 물품 상세 조회 |
| `POST` | `/api/items` | 분실물·습득물 등록 |
| `PUT` | `/api/items/{id}/status` | 처리 상태 변경 |
| `POST` | `/api/items/{id}/bookmark` | 북마크 변경 |
| `POST` | `/api/items/{id}/inquiries` | 문의 등록 |
| `GET` | `/api/items/{id}/inquiries` | 물품별 문의 목록 조회 |
| `GET` | `/api/pets` | 실종 반려동물 목록 조회 |
| `POST` | `/api/pets` | 실종 반려동물 신고 |
| `POST` | `/api/auth/login` | 로그인 초안 |
| `POST` | `/api/auth/register` | 회원가입 초안 |
| `POST` | `/api/support` | 고객센터 문의 등록 |
| `GET` | `/api/support/faq` | FAQ 조회 |

공공데이터 조회 예시:

```text
GET /api/public-items?start=1&end=50
```

화면의 새로고침은 서버 메모리를 다시 조회합니다. 외부 API는 서버 시작 시 최초 조회하고, 첫 성공 전에는 실패 후 30초마다 재시도합니다. 최초 저장 이후에는 매 정시(한국 시간 기준 하루 24회) 갱신합니다. `refresh=true`를 보내도 이 일정을 우회하지 않습니다.

`/api/public-items`의 `q`, `managementNumber`, `registeredDate` 검색 조건은 현재 메모리에 저장된 자료 안에서 적용됩니다. 조회 범위는 최대 1~50이며, `end`가 50을 넘으면 50으로 제한합니다.

| 응답 상태 | 의미 |
| --- | --- |
| HTTP 202, `loading: true` | 최초 조회 또는 실패 후 재시도 대기 상태. 아직 저장된 정보가 없으며 `message`, `retryAfterSeconds`로 안내 |
| HTTP 200, `cached: true` | 저장된 정보를 반환. `updatedAt`은 실제 저장 시각, `nextRefreshAt`은 다음 정시 |
| `refreshing: true` | 저장된 정보를 제공하면서 백그라운드 갱신 중 |
| `warning` 또는 `partial: true` | 일부 제공기관 조회 실패 또는 부분 자료 상태 |
| HTTP 400 | 잘못된 조회 범위 또는 날짜 형식 |

처음 준비 중에는 화면에서 약 3초 간격으로 저장 상태를 확인하고, 서버가 재시도 대기 중이라고 안내하면 약 30초 간격으로 확인합니다. 이 확인 요청은 외부 API를 직접 호출하지 않습니다.

## 공공데이터 처리 방식

- 서울시 자료는 등록일 또는 수령일의 연도가 2025년 이상이면 포함합니다. LOST112는 습득일이 2025년 이상인 자료를 포함합니다.
- 서울시 자료와 LOST112 자료는 동시에 조회합니다.
- 관리번호가 같으면 동일 물품으로 판단합니다.
- 관리번호가 다르면 물품명, 등록일, 보관장소를 기준으로 중복을 확인합니다.
- 중복 자료는 하나로 합치고 비어 있는 정보만 보완합니다.
- 공공데이터는 최대 50건을 서버 메모리에 저장합니다. 외부 API의 개별 조회 요청도 최대 50건으로 제한합니다.
- 서울시 자료는 첫 구간에서 전체 자료 수를 확인하고, 필요한 경우 마지막 구간을 추가 조회합니다. 제공기관에서 확인한 결과를 합쳐 최대 50건을 남기므로, 화면에 표시되는 수는 50건보다 적을 수 있습니다.
- 서버 시작 시 최초 조회하고 이후 매 정시마다 갱신합니다. 서버가 계속 실행 중이어야 정시 작업도 실행됩니다.
- 갱신 중이거나 실패하면 이전 저장 정보를 유지합니다. 메모리는 시간 만료로 삭제하지 않으며 서버 재시작 시 초기화됩니다.
- 최초 조회 중에는 API가 HTTP 202와 `loading: true`를 반환하고, 화면은 저장 상태만 다시 확인합니다.
- 최초 조회 실패 시에는 30초 후 재시도합니다. 한 번 정상 저장된 이후에는 매 정시 갱신하며, 갱신 실패 시 기존 정보를 유지합니다.
- 외부 API 요청별 대기시간은 각각 최대 15초이며, 서울시 추가 구간 조회에도 별도의 15초를 부여합니다.
- 전체 조회 작업은 최대 35초로 제한합니다. 서울시 조회는 최초 구간과 최신 구간을 합쳐 최대 2회 실행합니다. LOST112는 같은 전체 제한 안에서 병렬로 조회합니다.
- 초기 조회 실패·재시도 상태도 HTTP 202와 JSON으로 안내하며, 화면은 HTML 오류 응답을 JSON으로 해석하지 않습니다.

갱신은 `PublicItemsRefreshService`가 수행합니다. 정상 결과를 완성한 뒤 스냅샷을 교체하므로 화면 요청은 진행 중인 외부 조회가 끝날 때까지 기다리지 않습니다. 일부 제공기관만 성공하면 이미 저장된 정보는 유지하며, 최초 조회라면 부분 자료를 저장할 수 있습니다.

## Docker 실행

```powershell
docker build -t lostfind .
docker run --rm -p 8080:8080 `
  -e SEOUL_OPEN_API_KEY="서울시_API_키" `
  -e DATA_GO_KR_API_KEY="공공데이터포털_API_키" `
  lostfind
```

브라우저에서 `http://127.0.0.1:8080`으로 접속합니다.

## Cloudtype 배포 설정

- 배포 방식: `Dockerfile`
- 공개 포트: `8080`
- Dockerfile 경로: `Dockerfile`
- 환경변수: `SEOUL_OPEN_API_KEY`, `DATA_GO_KR_API_KEY`
- 실행 환경: Dockerfile에서 `Production`으로 지정

Cloudtype 환경변수에 사용할 API의 인증키를 등록한 후 GitHub 저장소와 연결하여 배포합니다. Dockerfile에 실행 명령이 있으므로 별도 시작 명령은 일반적으로 필요하지 않습니다.

로컬 수정은 배포 사이트에 자동으로 반영되지 않습니다. GitHub에 커밋·푸시하고 배포 완료를 확인해야 합니다. 서버 재시작·재배포 후에는 메모리가 초기화되므로 최초 조회가 다시 진행됩니다.

## 조회·실행 문제 확인

| 증상 | 확인 사항 |
| --- | --- |
| 실행할 프로젝트를 찾지 못함 | `LostFind.csproj`가 있는 폴더인지 확인 |
| `dotnet`을 찾지 못함 | .NET 10 Runtime이 아닌 SDK 설치 여부 확인 |
| 로컬 페이지에 접속할 수 없음 | 서버 창이 열려 있고 실제 수신 주소와 접속 주소가 일치하는지 확인 |
| 정보 준비 중이 계속 표시됨 | API 인증 설정, 외부 제공기관 연결 상태 및 서버의 공공데이터 갱신 로그 확인 |
| 최초 조회 실패 반복 | 개별 요청 15초·전체 35초 안에 응답이 완료되는지 확인. 실패 후 30초 대기 뒤 재시도 |
| API 응답이 JSON이 아닌 HTML | 잘못된 배포 경로 또는 배포 플랫폼의 오류 응답인지 HTTP 상태와 Content-Type 확인 |
| 수정한 색상이나 화면이 보이지 않음 | 로컬은 `Ctrl+F5`, 배포 사이트는 커밋·푸시 및 재배포 완료 여부 확인 |

## 현재 개발 단계의 제한사항

- 사용자 신고, 실종 반려동물, 문의 등은 서버 메모리에 저장되며 재시작 시 초기화됩니다. 일부 UI는 브라우저 localStorage를 사용하므로 서버와 저장 수명이 다릅니다.
- 팀원별 로컬 서버는 서로 다른 메모리를 사용합니다. 같은 GitHub 코드를 받아도 등록 자료가 자동으로 공유되지는 않습니다.
- 로그인·회원가입은 기능 초안으로 실제 회원 저장, 비밀번호 검증, 인증 토큰 검증 및 관리자 권한 제어가 구현되어 있지 않습니다.
- 사진 선택·미리보기는 있으나 실제 업로드 스토리지와 영구 저장은 구현되지 않았습니다.
- LOST112 자료를 사용하려면 별도의 공공데이터포털 인증키가 필요합니다.
- 공공데이터 캐시는 서버 메모리 방식이므로 서버 재시작 시 초기화됩니다.
- MySQL/MariaDB 등 실제 데이터베이스 연결은 아직 구현되지 않았습니다.
- 사용자 등록 물품과 반려동물에는 예시 데이터가 포함되어 있습니다. 공공데이터 목록과는 구분됩니다.
- 서비스 대상은 중랑구이지만 서울시 공공데이터는 현재 백엔드에서 중랑구로 제한하지 않습니다. LOST112 결과는 보관장소·기관·설명의 '중랑' 포함 여부로 지역을 좁힙니다.
- 공공데이터 50건 제한은 서비스에 저장하는 수량이며, 제공기관의 모든 물품을 검색하는 기능은 아닙니다.

- 서버 재시작 후에도 마지막 정상 공공데이터를 복원할 수 있는 영구 저장
- 분실물·습득물 자동 매칭 개선
